# 教程参考审查与改写决策

记录日期：2026-10-11（北京时间）

本轮目标是参考用户 Chrome 中的三个页面，完善 Siilas 的机场客户端使用教程。教程应帮助读者从确认机场接入条件，走到导入配置、实际连接、验证和排查，并能返回本站的原始测速记录核对节点表现。

## 三页参考的深度分析

### 1. flclash.cc：短流程清晰，但不能作为完整连接指南

教程将操作分成导入 URL、打开连接开关、选择节点和设置自启四段，配有图示。左右目录便于定位步骤，也有利于读者在软件和浏览器之间切换后继续阅读。可借鉴它按任务组织内容的方式，以及截图与步骤靠近的呈现方式。

流程省略了配置是否已选中或激活、如何确认实际访问成功，以及不同平台安装和权限差异。读者可能完成导入，却仍不知道当前使用的是哪份配置；也可能看到连接开关已开，便误以为所有应用都已经经过代理。

页面把系统代理描述成接管电脑所有请求，这一说法不能沿用。本站应说明系统代理主要影响遵循系统代理设置的应用；不遵循设置的应用需要另行确认。TUN 的覆盖范围与路由、权限和平台配置有关，也不能写成开启后必然接管所有流量。

这个域名未确认为 FlClash 官方来源。本站不把它作为官方下载入口，也不因页面名称和界面相似就赋予其官方身份。截图可以帮助理解第三方教程的表达方式，但不能充当本站完成安装或连接的证据。

**改写取舍：**保留短步骤、图文对应和易定位目录的优点；补上安装前判断、配置激活、连接验证及平台边界。自启作为可选设置，不放在首次连接成功之前。

### 2. clashbk/clash Wiki：操作链条较完整，但需去除过期与推广干扰

ClashMi 页面覆盖安装、URL／二维码／文件三种导入方法、配置激活、连接、模式、节点和更新，配有操作截图。它比只讲粘贴订阅链接的教程更接近完整用户任务。“导入配置”与“激活配置”分开尤其有用，适合借鉴到本站的新结构中。

页面写死了 v1.0.11.150，且混用 2025 与 2026 时间文案。不能把这个版本号写成当前最新版本，也不能把第三方页面的时间当作本站当前客户端验证日期。截图中的菜单应与实施时核对的客户端对应，版本差异需要在文字中说明。

页面还包含推广、优惠码等内容，这些内容与读者完成配置的任务无关，不进入本站教程。规则与全局模式的解释过于简略，本站需要说明模式如何影响分流，同时提醒代理组及其选择仍会影响实际行为，避免“规则模式始终最快”或“全局模式一定让所有请求走同一节点”这样的简化结论。

URL、二维码和文件是导入同类配置的不同入口，不应写成需要依次完成的三个步骤。订阅通常还需要更新；本地文件的导入与在线订阅的更新也不能混为一谈。

**改写取舍：**采用完整的操作链条与三种导入入口的并列说明；按官方来源核对实际界面，移除推广内容和未经核实的最新版本断言，补充规则／全局模式及更新行为的边界。

### 3. clashbk/clash README：适合辅助选型，不能代替安装与联网验证

README 按维护情况和支持平台列出客户端对照，能帮助读者在下载前缩小选择范围。它提示了不同客户端名称和平台覆盖，不必让所有读者都安装同一软件，这是本站平台选择部分可以借鉴的思路。

该仓库是第三方导航，不是所有客户端或代理核心的官方项目。导航中的维护标记和可用状态只能作为核对线索，不能替代官方发布记录、实际安装和连接验证。页面的大量推广内容也不作为客户端选择依据。

导航缺少如何确认设备架构、如何进入官方 Release，以及怎样区分安装包与源码压缩包。新手即使选对项目，也可能下载错误架构或把 Source code 当成安装包。因此，本站需要在平台选择与安装部分补充这些判断，再将读者引导到项目官方来源。

**改写取舍：**采用平台与客户端的对照思路；补充设备架构、发布入口和安装包识别，不把第三方绿灯、维护标签或推荐排名写成本站验证结论。

## 本项目的改写范围

本轮将 `/tutorial/` 从六个并列短卡片改成单页长文，以目录连接主要任务。长步骤使用纵向文章结构，避免在三栏卡片中挤入完整安装和排查内容。保留其他客户端和故障主题，不把页面改成只有软件下载入口的文章。

落地的内容顺序如下：

1. **确认机场接入条件。**先区分通用订阅与官网指定客户端。机场账号不必然是第三方客户端的登录账号；不支持通用订阅的机场应按自己的官网文档操作。
2. **按平台选择客户端。**说明系统、设备架构、官方发布入口与安装包识别，呈现 FlClash、ClashMi、Clash Verge Rev 的适用路径。支持情况以核对后的官方说明为准。
3. **完成客户端配置。**分别介绍三个客户端的导入、配置选择或激活、连接、模式、节点及更新。不同客户端的菜单和截图分清，不把 FlClash 的界面套进 Clash Verge Rev 步骤。
4. **解释连接范围。**准确区分系统代理与 TUN、规则与全局，说明权限、应用行为及配置可能带来的差异。
5. **验证实际使用。**从配置存在、连接状态，到网页、出口地区和具体应用逐层确认，避免把绿灯、节点延迟或单次测速视为全部服务正常的证明。
6. **提供故障决策表。**分别处理导入失败、配置未激活、连接后无法访问、速度慢和单个服务不可用。先排查条件，再引导到相应步骤。
7. **连接本站实测。**保留固定测试条件、原始测速和测试方法入口，提醒读者按机场、节点、日期和实际网络判断结果。

Shadowrocket 保留独立小节，不能因本轮参考以 Clash 客户端为主而删除。协议选择保留 VLESS／SS 的现有兼容性边界，不把某个协议包装为必然更快或更稳定。

不新增未经实际操作的安装截图、平台实测结论、速度提升承诺或机场推荐评级。参考分析与本站客户端实测应有清晰来源区分。

本站测试客户端以机场专属客户端和 FlClash 为主。教程采用参考页整理 Clash Verge Rev 或 ClashMi 的操作，不表示本站已在所有系统或当前版本上完成实测。公开测试环境与原始记录继续以各条样本为准。

已有商业资料中的两项具体边界适合融入教程：Flybit 的一键导入不等于连接已经成功；拼好连重置订阅会使旧链接失效，重置订阅与重置流量是不同操作。这些说明来自本地机场资料，不新增兼容性或性能断言。

## SEO 与信息结构决策

标题、描述和 H1 继续围绕机场客户端配置与故障排查。客户端名应与最终操作内容对应，避免仅为覆盖名称堆砌关键词。主要任务采用 H2，客户端内部的安装、导入、激活和验证步骤采用 H3；页面顶部目录直接链接稳定锚点。

单页长文与目录是本轮内容决策，不声称增加字数或分节本身就能提升排名。新增内容的价值应来自读者能够完成配置、理解条件并找到对应排查步骤。

已补充真实作者、来源、修改日期、`TechArticle` 与面包屑结构化信息。页面可见信息与结构化数据保持一致；复核日期表示本次教程整理，而不是软件全平台测试日期。后续仅相关香港样本的新增会推进教程数据修改日期，其他地区新增测速不推进该页日期。结构化数据不作为排名或特殊展示的保证。
